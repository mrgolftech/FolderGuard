# FolderGuard GUI v3.2 设计与验收说明

## 单页交互设计

- 无侧边栏，默认单页浅色工作台。
- 顶部：产品名称和“刷新状态”；只有成功载入有效 NTFS 目录后才允许刷新。
- 目标文件夹：默认空路径。允许浏览已有文件夹，或输入完整路径点击“载入目录”；若输入目录不存在，创建前需确认。
- 当前状态摘要：分别展示顶层 ACL 是否保护继承、拒绝 DELETE 规则、+S 和 +H。**仅取磁盘实际值，不取设置草稿。**
- 设置选项：只暴露快速 ACL、+S、+H。每项高亮是“待应用值”，但在载入、刷新、应用完成后会立即用真实状态重置。变更未提交前，摘要保持真实状态。
- 底部：红色“应用设置”按钮作为唯一的写入入口。无目录时禁用全部权限操作；执行期间禁用控件，避免重复提交。
- 操作完成：异步工作线程完成后重新调用 ReadStatus，更新摘要及设置项，并显示包含操作、返回信息、耗时、最新状态的弹窗。
- 页脚：版本号和 GitHub 链接，调用系统默认浏览器打开。

## 状态流

```text
首次启动（空路径、不可操作）
   ↓ 浏览 / 手动输入并载入
Guard + ReadStatus
   ↓
实际状态摘要 + 设置选项同步
   ↓ 修改选项（仅修改草稿）
“待应用变更”提示；磁盘摘要保持不变
   ↓ 点击应用设置 + 必要时确认 ACL
后台顺序执行 QuickLock/QuickUnlock、System、Hidden
   ↓
重新读取 NTFS 状态，无论成功或失败都同步摘要/高亮
   ↓
完成结果弹窗
```

快速加锁会**强制启用 +S**；因此选择 ACL 开启时，System 设置草稿同步勾选。在 ACL 草稿开启时，不能取消 +S。取消 ACL 后 +S 不会自动移除，可以独立选择是否取消。

## 实现约束

- Windows 7 SP1 与 Windows 10 兼容目标。Win32 API + Direct2D 1.0，MSVC 2022 静态运行库，C++17。
- UAC Manifest：requireAdministrator，当前 GUI 在启动时即要求管理员权限。
- 后端仍保留完整模式函数供旧代码/测试使用，但 **GUI v3.2 不再向用户提供完整递归操作入口**。
- 快速 ACL：仅顶层目录，不能依靠它保护所有子文件已知路径的读取。
- 顶层拒绝 DELETE/DELETE_CHILD 规则仍有父目录 DELETE_CHILD 绕过风险；不能称为绝对防删除。
- 解锁使用继承重置而非原 ACL 快照恢复，可能移除自定义 ACE。
- +S 和 +H 不提供数据机密性。需要真正保护内容请使用加密。
- GUI 不调用系统回收站，也不允许对系统根目录直接加锁。

## 自动化验收

Windows Server 2022 GitHub Actions：

- x86 / x64 构建；
- 13 项 NTFS ACL/属性后端临时目录测试；
- GUI 启动后默认路径为空；
- 未选目录时操作禁用；
- `--path` 载入测试目录；
- 先调整 +S、+H 选项，验证尚未写入磁盘；
- 应用设置后验证实际属性及完成弹窗；
- 刷新后选项重新同步，取消属性后再次应用；
- GUI 快速 ACL 加锁/解锁验证继承保护状态，并检查自动 +S；
- 抓取真实运行窗口的“未载入目录”和“已载入目录”两种截图。

**尚未验证**：Windows 7/Windows 10 真机、不同 DPI、8 万文件的完整操作、普通账户与管理员跨身份访问控制、右键删除行为的全部 ACL 边界。
