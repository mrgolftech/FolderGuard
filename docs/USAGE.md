# 使用说明（Windows 10/11）

适用版本：FolderGuard v2.3 / Windows PowerShell 5.1 / NTFS。

## 1. 安装与启动

将两个文件放在相同目录：

```text
D:\Tools\FolderGuard\
├── FolderGuard.ps1
└── Start-FolderGuard.cmd
```

双击 `Start-FolderGuard.cmd`，同意 UAC 管理员权限提示。或者在**管理员 PowerShell** 中运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\Tools\FolderGuard\FolderGuard.ps1"
```

启动器只负责请求提升权限；主要功能在 PowerShell 脚本中。请不要独立运行旧版 `FolderGuard.cmd`。

## 2. 创建或选定目标

选择菜单 **1**，输入本地磁盘下的**绝对路径**，例如：

```text
E:\MyVault
E:\$RECYCLE.BIN$
```

第二个名称是用户自建目录（末尾多一个 `$`），**不是** Windows 回收站 `E:\$RECYCLE.BIN`。菜单会在目录不存在时尝试创建。请确认选中的始终是**你自己建立的数据目录**。

目标不得为盘符根目录、Windows 系统目录、真实回收站或链接/联接点目录。脚本包含若干路径保护检查，但不能替代操作者核对。

## 3. 推荐操作流程

### 首次加锁（先在空测试目录操作）

1. 菜单 **1**：选择 `E:\FolderGuard-Test`；
2. 在该目录中放一个**不重要的测试文件**；
3. 菜单 **4**：添加 `+S +H`，使资源管理器默认隐藏目录；
4. 菜单 **8**：**快速加锁**，或菜单 **2**：**完整加锁**；
5. 菜单 **6**：查看系统/隐藏属性及根目录 ACL；
6. 使用**另一个标准用户账户**尝试访问（请勿用真实资料测试删除）。

> 加锁操作会自动加 `+S`，但不自动加 `+H`。如需完全隐藏，请先选菜单 4。

### 需要存入或取出文件时

- 快速加锁对应菜单 **9** 快速解锁；
- 完整加锁对应菜单 **3** 完整解锁；
- 若文件夹仍被隐藏，可选菜单 **5** 取消 `+S +H`，或手动输入完整目录路径；
- 移入/移出文件后，重新选择加锁；
- 所有解锁操作**不主动清除 `+S` / `+H`**。

**重要：** 若此前运行过完整加锁，快速解锁仅恢复顶层目录，不会恢复内部文件的 ACL；必须根据需要执行完整解锁。

## 4. 菜单明细

| 菜单 | 操作对象 | 效果 |
| --- | --- | --- |
| 1 | 自定义目录 | 选择或创建 |
| 2 | 目录 + 现有子项 | 完整加锁：限制访问，顶层拒绝删除并自动 +S |
| 3 | 目录 + 现有子项 | 完整解锁：继承父权限，递归重置 ACL |
| 4 | 目标目录 | 设置 +S +H |
| 5 | 目标目录 | 取消 +S +H |
| 6 | 顶层目录 | 显示属性、ACL 和防删除状态 |
| 7 | 目标目录 | 尝试用资源管理器打开 |
| 8 | 顶层目录 | 快速加锁：禁用继承，仅管理员/SYSTEM 可访问；顶层拒绝删除；+S |
| 9 | 顶层目录 | 快速解锁：恢复顶层继承 ACL |
| 0 | — | 退出 |

### 快速模式与完整模式

快速模式**不主动枚举和修改子文件**，适合主要防止浏览顶层目录的场景。它不保证已知内部文件完整路径后无法直接打开该文件。

完整模式需要批量处理目录内部对象。数万个文件时耗时可能明显增加；脚本使用 `icacls /q` 减少成功信息输出。在控制台没有完成提示前，不建议重复启动相同操作。

## 5. 加锁前如何备份 ACL

当前程序**不提供原始 ACL 快照恢复**。解锁使用继承权限重置，因此特殊自定义权限可能丢失。

推荐先在非受保护位置备份原 ACL（管理员 PowerShell）：

```powershell
$path = 'E:\FolderGuard-Test'
icacls.exe $path /save 'D:\folderguard-acl-backup.txt' /t
```

查看备份文本并确保保存成功。需要还原时，请先确认权限恢复的作用范围和路径层次；例如目录位于 E 盘根目录，备份包含此目录名时，可以在管理员窗口执行：

```powershell
icacls.exe 'E:\' /restore 'D:\folderguard-acl-backup.txt'
```

**不要**对整个 E 盘执行 `/reset /t`；备份/还原命令应先在空测试目录确认路径映射无误。

## 6. 常见问题

### Q：提示成功加锁，但右键仍可删除？

NTFS 删除检查可能接受两种授权之一：**对象自身的 `DELETE`** 或 **父目录上的 `DELETE_CHILD`**。本工具在目标目录上加拒绝规则，但**不会更改父目录（尤其盘符根目录）的 ACL**。因此防删除只能称为尽力限制，**不能保证防止删除**。

严禁用包含重要文件的目录测试右键删除。若要提升保护强度，建议把数据放到专门父目录下，由专业权限方案管理父目录的 `DELETE_CHILD`。

### Q：有 `+S +H` 就安全了吗？

不是；它们只影响文件系统属性与资源管理器显示。能直接访问数据的账户仍可能读取内容。敏感数据应使用 BitLocker、EFS 或加密容器。

### Q：解锁仍显示拒绝访问？

先检查是否以管理员身份执行，及内部子文件是否曾完整加锁：

```powershell
$path = 'E:\FolderGuard-Test'
icacls.exe $path
```

如果是完整加锁，请使用菜单 3；必要时在**明确理解权限覆盖风险**的前提下，先于空测试目录手工验证：

```powershell
icacls.exe $path /inheritance:e
icacls.exe $path /reset /t
```

若上述命令失败或目录原本存在精细权限，不要盲目继续 `takeown` 或递归重置，请先保留 ACL 输出与错误日志诊断。

### Q：为什么解锁后目录仍不可见？

解锁不清除文件属性。请选择菜单 **5** 去除 `+S +H`。

### Q：脚本会访问真正的回收站目录吗？

项目目标不是操作系统回收站。真正的 Windows 回收站常用 `$RECYCLE.BIN`，请勿选择。自建 `$RECYCLE.BIN$` 只是相似名称，不意味着获得系统特殊保护。

## 7. 使用边界

- 仅支持本地绝对盘符路径；推荐 NTFS。
- 操作 ACL 时需要管理员权限。
- 不提供文件加密、文件读写功能、进程级白名单或管理员隔离。
- 不能保证防删除，也不能保证防止管理员接管/离线读取。
- 运行前建议备份重要数据，并在小型测试目录验证。
